# SSRI Medication Decision Vignettes

## Overview

This directory contains tools for exploring the Habermas Machine using SSRI (antidepressant medication) decision-making vignettes. The vignettes are split between **sacred values cases** (religious/moral objections) and **secular trade-off cases** (cost, side effects, efficacy considerations).

## Quick Start Guide

### 1. Understand the Architecture

Read the **step-by-step walkthrough**:
```bash
python example_deliberation_walkthrough.py
```

This script demonstrates:
- How to initialize the HabermasMachine
- How data flows from opinions → statements → rankings → consensus
- What happens in opinion rounds vs critique rounds
- How to access deliberation history and explanations

### 2. Generate Test Vignettes

Create 50 SSRI decision vignettes:
```bash
python create_ssri_vignettes.py
```

This generates `ssri_test_vignettes.json` with:
- **25 sacred values cases**: Religious/moral objections to SSRIs
- **25 secular trade-off cases**: Practical cost/benefit considerations

### 3. Run Batch Deliberations

Process all vignettes and generate statistics:
```bash
export GOOGLE_API_KEY="your_api_key_here"
python run_batch_deliberations.py
```

This creates:
- `deliberation_results.csv`: Detailed metrics for each vignette
- `summary_statistics.txt`: Comparison of sacred vs secular cases

## Architecture Summary

### The Habermas Machine

The Habermas Machine is an AI-mediated democratic deliberation system with these components:

```
┌─────────────────────────────────────────────────────────────┐
│ HabermasMachine (Orchestrator)                              │
│  - Manages deliberation rounds                              │
│  - Tracks history                                           │
│  - Coordinates all components                               │
└─────────────────────────────────────────────────────────────┘
                            ↓
        ┌──────────────────────────────────┐
        │                                  │
        ↓                                  ↓
┌─────────────────┐              ┌──────────────────┐
│ Statement Model │              │  Reward Model    │
│ Generates       │              │  Ranks           │
│ consensus       │              │  statements per  │
│ statements      │              │  citizen         │
└─────────────────┘              └──────────────────┘
        ↓                                  ↓
        └──────────────┬───────────────────┘
                       ↓
          ┌──────────────────────┐
          │ Social Choice Method │
          │ (Schulze Voting)     │
          │ Aggregates rankings  │
          └──────────────────────┘
```

### Data Flow

```
INPUT: Question + Citizen Opinions
  ↓
STEP 1: Generate N candidate consensus statements
  ↓
STEP 2: Each citizen ranks all candidates
  ↓
STEP 3: Schulze method aggregates rankings
  ↓
OUTPUT: Winning statement + all candidates sorted
  ↓
INPUT: Critiques of winning statement
  ↓
STEP 4: Generate new candidates (incorporating critiques + previous winner)
  ↓
STEP 5: Rank, aggregate, select refined winner
  ↓
FINAL: Refined consensus statement
```

## Vignette Format

### JSON Structure

```json
{
  "id": "SSRI_SACRED_001",
  "question": "Should a devout Christian patient accept SSRI antidepressants when...",
  "affirming_statement": "The patient should accept SSRI treatment as...",
  "negating_statement": "The patient should NOT accept SSRIs as...",
  "topic": "ssri_sacred_values",
  "split": "test",
  "sacred_value_type": "religious_authority",
  "religious_tradition": "christianity"
}
```

### Fields

- **id**: Unique identifier (e.g., `SSRI_SACRED_001`, `SSRI_SECULAR_015`)
- **question**: The deliberation question/scenario
- **affirming_statement**: Pro position
- **negating_statement**: Con position
- **topic**: Category (`ssri_sacred_values` or `ssri_secular_tradeoffs`)
- **split**: Dataset partition (typically `test`)
- **sacred_value_type** (sacred only): Type of moral conflict
- **religious_tradition** (sacred only): Religious framework
- **tradeoff_type** (secular only): Type of cost/benefit tradeoff
- **primary_concern** (secular only): Main practical consideration

## Metrics Tracked

The batch processing script tracks these metrics:

### Agreement Metrics
- **Opinion round agreement score**: Consensus level in round 1
- **Critique round agreement score**: Consensus level in round 2
- Higher scores indicate stronger agreement among participants

### Endorsement Metrics
- **Endorsement mean**: Average ranking of winner (0 = best)
- **Endorsement std dev**: Variability in winner rankings
- Lower mean = stronger preference for winner

### Rejection Metrics
- **Number of statements rejected**: Universally disliked options
- **Worst statement**: Lowest-ranked alternative

### Processing Metadata
- **Processing time**: Seconds per deliberation
- **Success/failure tracking**
- **Timestamp**: When deliberation occurred

## Example Usage

### Single Deliberation

```python
from habermas_machine import machine, types
from habermas_machine.social_choice import utils as sc_utils
import json

# Load a vignette
with open('ssri_test_vignettes.json', 'r') as f:
    vignettes = json.load(f)

question = vignettes[0]['question']

# Initialize
hm = machine.HabermasMachine(
    question=question,
    statement_client=types.LLMCLient.AISTUDIO.get_client('gemini-1.5-flash'),
    reward_client=types.LLMCLient.AISTUDIO.get_client('gemini-1.5-flash'),
    statement_model=types.StatementModel.CHAIN_OF_THOUGHT.get_model(),
    reward_model=types.RewardModel.CHAIN_OF_THOUGHT_RANKING.get_model(),
    social_choice_method=types.RankAggregation.SCHULZE.get_method(
        sc_utils.TieBreakingMethod.TBRC
    ),
    num_candidates=4,
    num_citizens=5,
    verbose=True
)

# Opinion round
opinions = ["Opinion 1", "Opinion 2", "Opinion 3", "Opinion 4", "Opinion 5"]
winner1, candidates1 = hm.mediate(opinions)

# Critique round
critiques = ["Critique 1", "Critique 2", "Critique 3", "Critique 4", "Critique 5"]
winner2, candidates2 = hm.mediate(critiques)

print(f"Final consensus: {winner2}")
```

### Analyzing Results

```python
import pandas as pd

# Load results
df = pd.read_csv('deliberation_results.csv')

# Compare sacred vs secular
sacred = df[df['vignette_type'].str.contains('sacred')]
secular = df[df['vignette_type'].str.contains('secular')]

print(f"Sacred cases average agreement: {sacred['opinion_round_agreement_score'].mean():.3f}")
print(f"Secular cases average agreement: {secular['opinion_round_agreement_score'].mean():.3f}")

# Find most/least consensus
most_consensus = df.nlargest(5, 'critique_round_agreement_score')[['vignette_id', 'critique_round_agreement_score']]
least_consensus = df.nsmallest(5, 'critique_round_agreement_score')[['vignette_id', 'critique_round_agreement_score']]

print("\nMost consensus:")
print(most_consensus)

print("\nLeast consensus:")
print(least_consensus)
```

## Research Questions

These vignettes can help explore:

1. **Do sacred values reduce consensus?**
   - Compare agreement scores between sacred vs secular cases
   - Hypothesis: Sacred values may make compromise more difficult

2. **Which types of concerns are most divisive?**
   - Examine variance in rankings by vignette category
   - Identify which sacred_value_types or tradeoff_types have lowest agreement

3. **Does deliberation increase consensus?**
   - Compare opinion_round vs critique_round agreement scores
   - Test if refinement through critique improves consensus

4. **What patterns emerge in rejected statements?**
   - Analyze which candidate statements get universally rejected
   - Identify common features of unpopular positions

5. **How do processing times differ?**
   - Compare sacred vs secular processing times
   - May indicate complexity of deliberation

## Troubleshooting

### API Key Issues

```bash
# Check if set
echo $GOOGLE_API_KEY

# Set temporarily
export GOOGLE_API_KEY="your_key_here"

# Set permanently (add to ~/.bashrc or ~/.zshrc)
echo 'export GOOGLE_API_KEY="your_key_here"' >> ~/.bashrc
```

### Rate Limiting

If you hit rate limits:
1. Reduce `max_vignettes` in batch script
2. Increase sleep time between vignettes (currently 2 seconds)
3. Use `gemini-1.5-flash` instead of `gemini-1.5-pro`

### Memory Issues

For large-scale processing:
1. Process in smaller batches (use `max_vignettes`)
2. Results are saved incrementally every 5 vignettes
3. Can resume from last saved batch if crash occurs
